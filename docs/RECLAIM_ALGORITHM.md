# 联合调整优化器

`reclaim_from_text` 在指定调整预算内选择一组可移动日程，使有效专注分钟数达到目标。固定日程始终保留。每个可移动日程默认成本为 1，可在独立成本文件中用 `cost EVENT_ID POSITIVE_INT` 覆盖。

## 问题边界

- 每天最多 200 项日程，其中最多 16 项可移动，其余必须标记 `fixed`。
- 单项成本为 1 到 10000；预算为 0 到 160000；目标为 1 到 1440 分钟。
- 阈值为 1 到 1440 分钟，恢复时间为 0 到 1440 分钟。
- 日程移除表示移出当前日，不负责将其安排到其他日期。

输入超过边界会返回错误，不会默默截断。成本文件拒绝未知 ID、固定日程 ID、重复声明及非正整数。

## 目标与确定性

首先选择达到目标且总成本最小的方案。成本相同，依次选择专注分钟数更多、移除项数更少、移除 ID 排序后字典序更小的方案。输入行顺序不影响结果。`largest_focus` 是描述字段，不参与优化目标。

结果同时返回成本与专注分钟数的 Pareto 前沿。前沿中的每个点都不存在成本更低且专注时间不少于它的方案；同一成本只保留按上述规则确定的代表。目标不可达时，`best_focus_under_budget` 给出预算内可实现的最大专注分钟数，`target_shortfall_minutes` 给出差额。

## 算法与正确性

为可移动日程按 ID 编号，枚举所有二进制子集。子集成本通过去掉最低有效位的已知成本递推。成本超过预算的子集无需进行时间计算；其余子集保留所有固定日程和未移除日程，并重新计算区间合并、恢复与专注阈值。最多枚举 65536 个子集。

每个合法的移除方案与一个子集一一对应，因此枚举覆盖全部预算内方案。每个成本桶记录该成本下的最优代表；按成本递增扫描，第一个达到目标的桶给出最小成本。仅当专注分钟数严格超过此前所有桶时输出前沿点，这恰好删除所有受支配点。

证明不依赖目标函数的单调性，也不使用未经证明的专注时间上界剪枝。当前固定恢复模型下，删除忙碌区间会扩大或合并空闲区间；未发现删除反而减少专注时间的反例。实现仍对每个候选独立重算，以免后续更改恢复模型时破坏正确性。

令可移动项数为 m、全部日程数为 n、预算为 B。当前直接过滤实现最坏时间约为 O(2^m × n × m)，存储包括 O(2^m) 成本表和 O(B × m) 成本桶。该算法面向单日的小规模精确决策，规模上限是明确的工程约束。它不声称适合任意规模排程。

## 可复现验证

运行 `moon test --target js`。测试包括：只有联合移除才有收益的重叠日程、固定日程导致的不可行结果、自定义成本、三层确定性规则、输入边界，以及 16 项可移动日程全部 65536 个子集的回归用例。

另有独立逐分钟占用数组作为计算依据，对 3 种恢复时间、3 种阈值和 7 种预算共 63 个组合校验最优成本、最大专注时间及完整前沿。该 oracle 不调用生产区间合并函数。
