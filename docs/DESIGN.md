# 设计说明

## 目标

做一个轻量、离线、结果确定的 MoonBit 工具。使用者手工写下日程，工具揭示“看起来空闲、实际上很难专注”的时间碎片，并通过移除模拟找出最值得协商的一场安排。

## 从 MoonLayout 借鉴的模式

| MoonLayout 的工程方式 | MoonPocket 中的对应实现 |
| --- | --- |
| 接收上游坐标快照，独立验证 | 接收人工日程快照，独立计算 |
| MoonBit 纯计算核心 | MoonBit 解析、区间分析、模拟与渲染 |
| .snapshot 文本，可提交 Git | .day 文本，可审阅和比较 |
| JSON 违规报告 + SVG 标注 | JSON 专注报告 + SVG 时间轴 |
| 阈值和 0/1/2 退出码 | 专注预算阈值和 0/1/2 退出码 |
| 核心测试 + Node CLI 测试 | 数学边界测试 + 命令行集成测试 |

## 边界

核心对区间合并后做补集计算。移除模拟每次从剩余原始安排重新合并，避免把重叠会议的总时长错误算作收益。安排最多 200 条，以限制逐项模拟成本。恢复只在合并后的 busy 区间结束后计算一次；两个无间隙的会议视为连续忙碌。

不把 JSON 序列化当作哈希，不声称具备稳定指纹机制。不读取个人日历、不接入 AI、不自动重排。恢复时间和专注门槛只是显式参数。建议不考虑安排的重要性、可移动性或团队约束。

## 文件组织

- `src/core/`：可复用核心、SVG 和 MoonBit 测试。
- `src/cmd/moonpocket/`：MoonBit CLI 与最小 JS FFI。
- `examples/`：两种日程及生成的报告与时间轴。
- `tests/`：Node 原生测试器验证 CLI 行为。

本地无需额外依赖，使用 MoonBit 标准库和 Node 内置模块。
